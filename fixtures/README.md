# Packed consumer verification

Run `bun run test:package` from this repository root for a built npm tarball, an isolated installation, Node SSR checks, compressed-size/graph checks, and a production Next consumer. Run `bun run test:browser` to add plain React and production Next browser tests and screenshots. Browser verification already includes the package checks; running both separately is unnecessary.

Both commands build and inspect the published package distribution in an isolated consumer. They use one temporary dependency installation containing Next, React, and the actual tarball. Tailwind and its PostCSS plugin are fixture development dependencies used only by the Next CSS pipeline; the plain React consumer shares the installation but imports no Tailwind code or styles. React and React DOM are excluded only from the isolated library-size measurements; browser tests load the real React runtime.

The Next fixture deliberately uses the supported production Webpack build and Tailwind/PostCSS pipeline, independent of Next package-import optimization or `transpilePackages`. Every run removes its generated `.next` directory because Webpack can retain stale transformations when a same-version package tarball is replaced. The installed distribution is also compared byte-for-byte with the freshly packed distribution. Its async Server Component renders a request-header value, controls, settings layout, and native links/forms. The verifier checks response HTML and the scripts/styles loaded by that route; it rejects UI component code or modal styles leaking into that static component graph. The data route additionally proves Notice and Toast presentation render on the server without component JavaScript. A separate route proves the chosen Lucide release renders SVG on the server.

The browser suite checks initially open and closed portal hydration, keyboard containment and restoration, nested Escape, typed confirmation reset, persistent dialogs, server-created children passed into dialogs, automatic scoped theme inheritance and updates, explicit themes, custom portal containers, and settings without JavaScript. Computed `backdrop-filter` assertions on both the dialog and backdrop protect against vendor-prefix declaration loss in plain CSS and Next/Tailwind builds. It captures settings/modal pages in dark/light themes at desktop/mobile sizes after opening animations settle.

Install the browser matching Playwright with `bunx playwright install chromium` if needed. `BNH_UI_CHROMIUM_EXECUTABLE` optionally selects an already-installed Chromium executable; the report records this override.

The browser command also accepts `--keep`, `--fixture-dir PATH`, and `--chromium PATH` in place of their environment variables, for example `bun run test:browser --keep --fixture-dir /path/to/bnh-ui-verify-example --chromium /path/to/chromium`. Other arguments are forwarded to Playwright for focused diagnostic runs.

Temporary fixtures are deleted after success by default. Set `BNH_UI_KEEP_FIXTURE=1` to preserve `artifacts/report.json`, bundle graphs, production build/server logs, HTML, browser traces on failure, and screenshots for review. The command prints their location. Failed runs retain their directory. Set `BNH_UI_FIXTURE_DIR` to that printed `bnh-ui-verify-*` directory to repack/reinstall and rerun without duplicating the dependency installation. Only harness-created directories immediately within the system temporary directory can be reused or removed.

Size gates measure minified output with gzip and Brotli, count transitive dialog/icon code, and track package download/unpacked bytes separately. The initial gates are Button JS ≤1.5 KiB gzip, Modal JS ≤20 KiB, theme plus Button CSS ≤3 KiB, Modal CSS ≤3 KiB, and settings CSS ≤5 KiB. A failing gate requires investigation rather than automatically widening its limit.

Feedback/menu verification covers keyboard and pointer selection, disabled items, nested Modal/menu Escape (including mounting races), portal theme inheritance, viewport collisions, live message semantics, timed-host hover/focus pausing, and no-JavaScript static feedback. Notice and Toast have a 4 KiB gzip JS budget and 3 KiB CSS budget each; ActionsMenu has a 30 KiB JS budget including Radix positioning/focus code and a 2 KiB CSS budget. Button graph/style checks explicitly exclude all three additions.
